# طراحی UI مدیریت منابع دانش

تیم ۸ از ۱۰. وضعیت: سند طراحی (وایرفریم متنی). پیاده‌سازی با تیم‌های دیگر.

## تصمیم مسیر

**انتخاب: گسترش `/dashboard/knowledge` — نه مسیر جدید، نه تب تنظیمات.**

دلیل‌ها:
- صفحه `/dashboard/knowledge` همین حالا آمار دانش هر تیم را نشان می‌دهد؛ منابع، همان دانش در حالت «ورودی» است. کنار هم بودنشان طبیعی است.
- `/manager/*` در این داشبورد فقط API است؛ مسیر UI تازه آنجا خلاف قرارداد فعلی است.
- تنظیمات (`/dashboard/settings`) برای پیکربندی سراسری سامانه است (درگاه‌ها، مدل‌ها)؛ منابع دانش دارایی هر تیم‌اند، نه تنظیم سامانه.
- ساختار پیشنهادی: `/dashboard/knowledge` دو تب می‌گیرد: «دانش» (فعلی) و «منابع». زیرمسیر جزئیات تیم هم حفظ می‌شود: `/dashboard/knowledge/[team]` تب «منابع این تیم» را هم می‌گیرد.

در ناوبری، آیتم «دانش» بدون تغییر می‌ماند؛ فقط داخل صفحه تب اضافه می‌شود.

## نقشه صفحه

### ۱. سربرگ صفحه (مشترک هر دو تب)

- `PageHeader`: تیتر «مدیریت دانش»، زیرتیتر «دانش و منابع آموزشی هر تیم».
- سمت چپ سربرگ (در RTL: انتهای چپ): دکمه `Button` وایب‌فارسی «افزودن منبع» (primary). این دکمه در هر دو تب دیده می‌شود چون افزودن منبع رایج‌ترین کار است.

### ۲. تب‌ها (`tabs` وایب‌فارسی)

- تب اول «نمای دانش» (محتوای فعلی صفحه، بدون تغییر).
- تب دوم «منابع دانش» (جدید، موضوع این سند).

### ۳. تب «منابع دانش»: نوار آمار بالا

چهار `StatCard` (کامپوننت `stat.tsx` موجود):
1. «کل منابع فعال» — عدد فارسی.
2. «رکوردهای دانش» — مجموع knowledge_chunks همه تیم‌ها، عدد فارسی.
3. «منابع نیازمند بازخوانی» — منابعی که از آخرین بازخوانی‌شان بیش از آستانه گذشته؛ اگر صفر نیست، رنگ هشدار ملایم (نه قرمز تند، تم graphite).
4. «میانگین تازگی» — مثلاً «۱۲ روز» با عدد فارسی.

### ۴. تب «منابع دانش»: فیلترها

یک ردیف فشرده بالای جدول:
- `Select` تیم: «همه تیم‌ها» + ۱۵ تیم (نام فارسی از TEAM_META).
- `Select` نوع منبع: همه / داک رسمی / بلاگ تخصصی / رقیب / مقاله پژوهشی.
- `Select` وضعیت: همه / فعال / غیرفعال / نیازمند بازخوانی.
- `SearchInput`: جست‌وجو در نام و URL.

### ۵. تب «منابع دانش»: جدول منابع (`table.tsx` وایب‌فارسی)

ستون‌ها (راست‌به‌چپ):
| ستون | محتوا |
|---|---|
| منبع | نام (پررنگ) + URL کوتاه‌شده در خط دوم با رنگ muted، قابل کلیک در تب جدید |
| تیم | بج نام فارسی تیم (`Badge`) |
| نوع | بج نوع: داک رسمی / بلاگ / رقیب / پژوهشی (رنگ خنثی، فقط متن متفاوت) |
| اعتبار | سه ستاره یا بج «درجه ۱/۲/۳»؛ درجه ۱ = داک رسمی، ۲ = بلاگ متخصص، ۳ = بقیه |
| آخرین بازخوانی | تاریخ شمسی نسبی («۳ روز پیش») + تاریخ کامل در `Tooltip` |
| رکوردها | تعداد رکوردهای استخراج‌شده از این منبع، عدد فارسی |
| وضعیت | `Switch` فعال/غیرفعال (تغییر فوری، بدون دیالوگ) |
| عملیات | سه دکمه آیکونی: بازخوانی دستی (RefreshCw)، ویرایش (Pencil)، حذف (Trash2) + دکمه «تست اتصال» (Plug/Zap) |

- سطرهای نیازمند بازخوانی: نوار باریک هشدار در لبه راست سطر (accent، نه کل سطر رنگی).
- صفحه‌بندی با `pagination.tsx` موجود؛ ۲۰ ردیف در صفحه.
- حالت خالی: `EmptyState` با متن «هنوز منبعی ثبت نشده» + دکمه افزودن.

### ۶. دیالوگ «افزودن / ویرایش منبع» (`dialog.tsx` وایب‌فارسی)

فیلدها:
- نام منبع (`Input`، اجباری، مثلاً «داک رسمی Next.js»)
- URL (`Input` با اعتبارسنجی، اجباری، چپ‌چین و ltr)
- تیم (`Select` از ۱۵ تیم، اجباری)
- نوع منبع (`Select`: داک رسمی / بلاگ تخصصی / رقیب / مقاله پژوهشی)
- درجه اعتبار (`segmented-control` با سه گزینه ۱/۲/۳ + توضیح کوتاه هر درجه زیرش)
- تناوب بازخوانی (`Select`: روزانه / هفتگی / ماهانه / دستی)
- توضیح (`Textarea`، اختیاری)
- سوییچ «فعال» (`Switch`)

دکمه‌های فوتر: «انصراف» (ghost) و «ذخیره منبع» (primary). هنگام ذخیره `spinner` داخل دکمه.
اعتبارسنجی خطا زیر هر فیلد با متن فارسی روان (نه متن فنی).

### ۷. عملیات سطری: جزئیات رفتاری

- **تست اتصال:** دکمه آیکونی؛ هنگام تست `spinner` جای آیکون؛ نتیجه با `toast`: موفق («اتصال برقرار شد، ۲۴۰ms») یا ناموفق («در دسترس نیست؛ کد ۴۰۴»). نتیجه در ستون وضعیت هم با بج موقت «آخرین تست: موفق/ناموفق» دیده می‌شود.
- **بازخوانی دستی:** با کلیک، سطر وارد حالت «در حال بازخوانی» می‌شود (آیکون چرخان + غیرفعال شدن دکمه‌ها)؛ پس از پایان toast نتیجه: «۱۲ رکورد تازه استخراج شد» یا «رکورد تازه‌ای نبود».
- **حذف:** `alert-dialog` تأیید با متن صریح: «منبع «X» حذف شود؟ رکوردهای دانش استخراج‌شده از آن حذف نمی‌شوند، فقط بازخوانی‌های بعدی متوقف می‌شود.» دکمه حذف با رنگ خطر ملایم.
- **ویرایش:** همان دیالوگ افزودن با مقادیر پرشده.

### ۸. نمای جزئیات تیم (`/dashboard/knowledge/[team]`)

تب سوم به این صفحه اضافه می‌شود: «منابع این تیم».
- بالای صفحه: همان StatCardهای کوچک مخصوص تیم (تعداد منابع فعال، رکوردها، آخرین بازخوانی).
- جدول منابع فقط همین تیم (بدون ستون تیم، بدون فیلتر تیم).
- دکمه «افزودن منبع» با تیم ازپیش انتخاب‌شده.

### ۹. APIهای موردنیاز (قرارداد برای تیم بک‌اند)

- `GET /api/knowledge/sources?team=&type=&status=&q=` → فهرست منابع
- `POST /api/knowledge/sources` → ساخت
- `PATCH /api/knowledge/sources/:id` → ویرایش / فعال‌سازی
- `DELETE /api/knowledge/sources/:id` → حذف
- `POST /api/knowledge/sources/:id/test` → تست اتصال
- `POST /api/knowledge/sources/:id/refresh` → بازخوانی دستی
- `GET /api/knowledge/sources/stats` → آمار نوار بالا

شکل رکورد منبع:
```json
{
  "id": "uuid",
  "name": "داک رسمی Next.js",
  "url": "https://nextjs.org/docs",
  "team": "dev",
  "type": "doc",
  "authority": 1,
  "refresh_interval": "weekly",
  "is_active": true,
  "last_fetched_at": "2026-10-10T08:00:00Z",
  "last_test_ok": true,
  "records_count": 48
}
```

## اصول بصری (یادآوری برای پیاده‌سازی)

- تم graphite وایب‌فارسی؛ خط مویی، بدون سایه، گوشه ۸.
- همه اعداد فارسی (`faNum`)؛ تاریخ‌ها شمسی نسبی.
- هیچ U+2014 در هیچ متنی.
- جدول در موبایل: هر سطر به کارت تاشو تبدیل می‌شود (نام + وضعیت در خط اول، جزئیات در `collapsible`)؛ عملیات سطری در موبایل با `dropdown-menu` سه‌نقطه.
- پیام‌های خطا فارسی روان؛ مثلاً به‌جای «fetch failed»: «به این نشانی نرسیدیم؛ دوباره تلاش کن.»

## ترتیب پیشنهادی پیاده‌سازی

1. APIهای منابع (تیم بک‌اند).
2. تب «منابع دانش» با جدول و فیلترها (فقط خواندنی).
3. دیالوگ افزودن/ویرایش + حذف.
4. تست اتصال و بازخوانی دستی.
5. نوار آمار و نمای جزئیات تیم.
