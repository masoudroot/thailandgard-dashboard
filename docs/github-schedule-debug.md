## علت دقیق

**اسکجولر داخلی گیت‌هاب تریگرهای schedule این ریپو را ثبت نکرده است.**

این یک مشکل سطح پلتفرم است، نه باگ در کد ما. شواهد:

1. سینتکس YAML کاملاً صحیح است (اجراهای دستی با همان فایل موفق‌اند)
2. تنظیمات ریپو سالم است (Actions فعال، ورک‌فلو active)
3. مشکل ریپو-واید است (هر دو ورک‌فلو affected هستند)
4. قانون ۶۰ روز عدم فعالیت نمی‌تواند علت باشد (ریپو ۱ روزه و بسیار فعال است)
5. ریپو فورک نیست

طبق مستندات انجمن گیت‌هاب (Discussion #208110)، این علامت دقیقاً — «`push` و `workflow_dispatch` کار می‌کنند ولی `event=schedule` صفر می‌ماند» — معمولاً به معنی **غیرفعال‌شدن خودکار اسکجولر** است. اما در این مورد، با توجه به فعال‌بودن ریپو، به احتمال زیاد **تأخیر در ثبت اسکجولر برای ورک‌فلوهای تازه‌ساخته‌شده** یا یک **باگ پلتفرم** است.

## راه‌حل‌ها

### راه‌حل ۱: صبر + re-arm (امتحان‌شده، نتیجه نامشخص)

کامیت خالی در 15:11 UTC پوش شد. اگر اسکجولر فقط تأخیر داشته، باید تا ۱۶:۱۱ UTC شروع به کار کند. اگر تا آن زمان صفر ماند، راه‌حل ۲ یا ۳.

### راه‌حل ۲: تماس با پشتیبانی گیت‌هاب (اگر راه‌حل ۱ جواب نداد)

این یک باگ پلتفرم است. باید تیکت باز شود با این جزئیات:
- ریپو: `masoudroot/thailandgard-dashboard`
- ورک‌فلو: `cycle-worker` (ID: 385566467)
- علامت: صفر `schedule` event در ۲+ ساعت با وجود `active` بودن

### راه‌حل ۳ (توصیه‌شده): معماری هیبرید — ورسل برای زمان‌بندی، گیت‌هاب برای اجرا

**به‌جای تکیه بر اسکجولر ناپایدار گیت‌هاب، از کرون ورسل (که قابل‌اعتماد است) برای تریگر `workflow_dispatch` استفاده کنیم.**

معماری پیشنهادی:
```
Vercel Cron (هر ۵ دقیقه)
    ↓ GET /api/cron/trigger-worker
    ↓ → GitHub API: POST /repos/.../actions/workflows/cycle-worker.yml/dispatches
GitHub Actions (موتور اجرا)
    ↓ npx tsx worker/cycle-worker.ts
    ↓ اجرای یک تیم
```

مزایا:
- زمان‌بندی قابل‌اعتماد (ورسل کرون)
- موتور اجرای قدرتمند (گیت‌هاب اکشنز با ۳۰ دقیقه تایم‌اوت)
- بدون وابستگی به اسکجولر گیت‌هاب
- با تصمیم معماری سازگار است (ورسل = زمان‌بند + داشبورد، گیت‌هاب = موتور اجرا)

معایب:
- نیاز به توکن گیت‌هاب در secrets ورسل
- یک لایه اضافه

### راه‌حل ۴ (جایگزین): اسکجولر خارجی

سرویس‌هایی مثل `cron-job.org` می‌توانند هر ۵ دقیقه به GitHub API درخواست `workflow_dispatch` بفرستند. ساده ولی وابستگی به سرویس ثالث.

## توصیه نهایی

**کوتاه‌مدت:** راه‌حل ۳ را پیاده کنیم. کرون ورسل همین حالا در `vercel.json` هست (`/api/cron/cycle-tick` هر ۲ دقیقه). کافی است آن را تغییر دهیم تا به‌جای اجرای مستقیم، ورک‌فلو گیت‌هاب را دیسپچ کند.
